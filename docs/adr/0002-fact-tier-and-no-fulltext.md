# ADR-0002：本地私有短周期缓存 + 两阶段事实锚定抽取 + 双层信息密度（预览简报 / 详情引用+评述）

- **状态**：已确认（2026-11-26，Human Maintainer 拍板升级信息质量与详情页内容模型）
- **背景**：单纯在内存中一次性将长文压缩成 ≤160 字后丢弃原文，会导致长文截断失真、AI 数字/日期幻觉难以核验、提示词调优无法离线重跑；同时，Web 卡片详情页需要比预览页更丰富的信息密度（基于完整正文的合规引用 + 法律实务评述），而公开仓库与对外双端必须严守 `AGENTS.md` 8.2「仅摘要/合理引用加链接，不整篇转载」的版权红线。
- **决策**：
  1. **物理隔离的本地私有缓存**：抓取的完整纯文本仅存于本机 `.cache/raw/`（写死 `.gitignore` + 测试接缝防误提交拦截，**7 天 TTL 自动清理**），供离线重跑与人工核验使用；**公开仓库 `data/` 与对外双端严禁落盘或输出原文全文**。
  2. **必填事实层级 + 两阶段事实锚定抽取**：
     - Stage 1 从本地完整正文抽取结构化事实卡片（发布机构、日期、文号/版本、效力状态、核心数据）与 1–3 句逐字合规短引文（`evidence_quotes`，单段受长度约束，仅作合理引用与核验依据）；超长法规文档按公告/核心条款分段提炼，并自动标记送入深度选题池。
     - Stage 2 基于事实卡片生成双层内容，并执行程序化忠实度校验（核对摘要中的数字/日期是否命中本地原文，未命中自动标 `needs_human_check: true`）；**事实层级**设为必填枚举并强制配 `unverified: true` 兜底。
  3. **预览层 vs 详情页双层信息密度**：
     - **预览层（列表卡片 / 公众号固定栏目）**：极简扫读——仅呈现 **≤160 字精炼摘要** + **1 句极简实务影响锚点（AI 初稿）**（Web 列表按 D-027 保持极简，公众号按 D-030 呈现摘要 + 1 句实务影响并引导「阅读原文」）。
     - **Web 卡片详情页（`detail_analysis`）**：基于完整正文呈现丰富内容——**3–5 条核心事实要点（`key_points`）+ 1–3 句合规原文短引文（`evidence_quotes`）+ 200–400 字法律实务深度评述（`legal_commentary`，人工终审前标「AI 初稿」）** + 一手信源直达链接。
- **理由**：通过「本机私有短周期缓存 + 公开库零全文」兼顾版权合规与离线可重跑性，通过「合规短引文 + 原创深度评述」既大幅降低 AI 幻觉与人工核验成本，又让公众号「阅读原文 → Web 详情页」真正具备增量阅读价值。
