## 4. 检查范围与要求

1. **来源**：优先立法与监管机构、法院公开文书、顶会论文、官方技术博客。二手媒体只能用来发现线索，表格里必须换成一手链接。
2. **一期的组织方式**：把 12 至 15 条当作“一天的内容”来排，按你认为读者最该先看的顺序，不按分类排。
3. **链接核验**：每条链接写明“检索日是否实际打开过”（已打开 / 未访问）。没打开过的不得当作已核实。
4. **摘要写法**：只写原文有的事实，数字、日期、机构名照抄原文；观点与事实分开写。实务影响锚点用“可能”“值得关注”这类措辞，不下确定结论，每条后面标“AI 初稿”。
5. **高风险条目**（立法、监管、司法文书、处罚）：写明发布机构、发布日期、文件版本、效力状态；无法核实的标“未核实”。不收涉及具体当事人负面事实的条目，也不收融资并购金额类条目。
6. **多样性**：五类各不少于 2 条；尽量覆盖中文与英文信源，但不为凑数收录质量低的条目。
7. **缺口**：文末列出未能找到合格条目的类别和原因。
8. **文件头**（原文照写）：“内部评审样本，不对外发布；仅摘要加链接，不转载原文”，之后写检索日期（2026-11-11 或你实际检索的日期）和未能核实的清单。
9. **提交方式**：你已有 GitHub 权限。请从最新 `main` 建分支 `gpt/ld-g1-04-sample-set`（分支前缀暂定，规范尚未定义），只新增 `docs/samples/LD-G1-04-sample-set.md` 一个文件，开 Draft PR，不合并。不改仓库中任何其他文件。如果你不能提交，把文件全文回复给 Human，由 Human 或 Claude 提交。
