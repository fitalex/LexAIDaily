## 一、背景与目标

Human 看过原型后提出三点：(1) 大盘卡片不展示“实务影响锚点”；(2) 卡片要按“信息重要程度”和摘要长度错落排版；(3) 占位标题里重复的“【示例占位】”太吵。字段表需先改，设计才有依据。

## 二、范围

- **输入**：`design/card-fields-v0.md`（v0.1）、`design/card-fields-v0.example.json`、D-016、D-019。
- **输出**：
  1. `design/card-fields-v0.md` 升到 **v0.2**（文件名不改）：
     - **展示层级**：新增一节，分“列表卡片”（大盘、分类筛选、历史归档列表）与“详情页”两层。列表卡片字段：核心标题、精炼摘要、原始信源链接、分类标签，加状态位（AI 初稿、未核实、事实层级）、日期与来源域名。**实务影响锚点移到详情页**，详情页保留其“AI 初稿”标识规则不变。
     - **新增显示字段“重要度”**：取值“头条 / 常规”，Human 终审时勾选，缺省“常规”。作用：决定列表卡片尺寸档位。AI 不得自行标“头条”。
     - **摘要长度**：给出“短摘要 / 常规摘要 / 长摘要”的字数建议区间（沿用 v0.1 的 60–120 字为宜，上限 160；短摘要 < 60 字不作缺陷处理，仍必填）。
     - **占位标记**：占位示例不再把“【示例占位】”写进标题；改为 JSON 字段 `placeholder: true`，UI 在卡片上显示小号“示例”标识。真实样本为 `false`。
     - **公众号栏目**是否沿用“四要素含实务影响”，本版写“待 Human 另定，LD-G1-03 开工前确认”，不替 Human 决定。
  2. `design/card-fields-v0.example.json`：升到 8 条，五类标签都有；至少 2 条 `importance: "头条"`；摘要长度覆盖短、常规、长三档；每条 `placeholder: true`；链接只用 `https://example.com/…`；`impact_anchor` 字段保留（供详情页用）；标题不含“【示例占位】”前缀。
- **可改文件**：`design/card-fields-v0.md`、`design/card-fields-v0.example.json`（D-011 期间本任务书授权 DeepSeek Harness 修改 `design/`）。
- **不可改文件**：`README.md`、`ROADMAP.md`、`AGENTS.md`、`docs/` 全部、其余 `design/`。
- **非范围**：不改五类标签与单标签规则（D-016）；不定义 Gate 2 数据契约；不改事实层级三档与条件显示规则；不写视觉样式数值。

## 三、冻结边界

README 与 ROADMAP 仍写“标准单元 = 核心标题 + 精炼摘要 + 实务影响锚点 + 原始信源链接”。本任务只改**列表卡片的展示**，不改这两份冻结基线。字段表须在“边界声明”写明：该展示层级由 Human 2026-11-11 指示（D-019）；基线文字是否同步修改由 Human 决定，Agent 不改。
