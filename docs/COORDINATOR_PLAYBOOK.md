# 协调者操作手册（Claude）

本手册规定 Claude 作为 LexAIDaily 协调者的日常做法。规则以 [AGENTS.md](../AGENTS.md) 为准，冲突时 AGENTS.md 优先。

## 1. 每次会话开始（必做）

Claude 不依赖聊天记忆，任务事实以仓库中已核验的记录为准；下面的步骤替代“记得上次做到哪”。

1. 读 [STATUS.md](coordination/STATUS.md)：当前 Gate、各任务状态、Human 待办、A 级台账。
2. 开放的 PR 与 Issue：公开页面直接读取，PR diff 与 CI 结果请仓库操作员（GPT 网页版）或 Human 回传；与 STATUS 对照，先修正不一致处。
3. 确认 `main` 最新 commit SHA，检查在途任务书的基准是否过期。
4. 按优先级处理：待复核的 PR → 待 Human 决策的事项 → 新任务。
5. 会话结束前把状态变更写回 STATUS（交仓库操作员提交 PR），否则下次会话会丢失。

## 2. 拆分任务书

原则：

- 一个任务 = 一个 Owner = 一个 PR，可独立验收。
- DoD 必须可验证（命令、文件、截图或链接），不写“做得好”。
- 文件范围明确，尽量让不同任务不改同一文件；必须同改时先排写入顺序。
- 先契约后实现：数据契约、接口先行，消费方任务依赖它。
- 研究、实现、审计分开，同一 Agent 不同时担任实现与审计。
- 体量以一次能审完为限，超出就拆。

步骤：

1. 从 ROADMAP.md（入库前以 Human 提供的版本为准）当前 Gate 的核心任务与验收标准列出交付物。
2. 按执行者能力拆分，画出依赖。
3. 判定 A/B 级（AGENTS.md 3.1）：按整体目标和累计变更判级，拿不准按 B 级，并在台账写明所属整体目标。
4. 判定是否触发独立审计（AGENTS.md 6.1）。
5. 用 [任务书模板](templates/TASK_BOOK.md) 写任务书。
6. 登记到 STATUS 看板与 [任务书索引](daily-specs/README.md)。

## 3. 选择执行者

| 任务特征 | 执行者 | 备注 |
|---|---|---|
| 核心架构、数据契约、站点、导出脚本、CI；Gate 1 设计系统与 UI/排版原型（Figma MCP + 图像生成） | Codex | 涉及密钥、外部服务、费用按 B 级并触发审计。Codex 同时承担工程与 UI，派发按依赖排序，不并行压入多个大任务 |
| 信源适配器、解析去重、单测回归、缺陷复现、对 Codex 成果交叉测试 | DeepSeek Harness | 不判定信源可信度，不改数据契约 |
| 文档、索引、归档、版本一致性 | Antigravity | 不写代码与设计稿 |
| 大范围联网调研、独立第二意见、审计、高风险核验 | GPT 网页版 | 用[交接包](templates/HANDOFF_PACKET.md)，Human 粘贴 |
| 提交文件、建分支与 Issue/PR、读回 diff 与 CI | GPT 网页版（仓库操作员） | 遵守 AGENTS.md 6.6；Claude 核对提交与原文一致 |
| 任务书、治理与标准类草案、协调类工作 | Claude | 自动触发 6.1(d) 审计 |

执行者拒单或不可用时，回到 Claude 修订任务书或改派。不得让 Owner 复核自己的成果。

## 4. 派发

- **A 级**（以经 Human 确认的 D-001 为依据）：Claude 在 STATUS 的 A 级台账登记授权，把任务书与台账更新交仓库操作员提交，再通知 Human 触发执行者。
- **B 级**：写决策包（第 7 节）交 Human，授权后才派发。

给 Human 复制的派发话术：

**Codex / Antigravity / DeepSeek Harness**

```
请先阅读仓库根目录 AGENTS.md，再阅读任务书 docs/daily-specs/<任务号>.md。
从最新 main 建分支 <codex、ag 或 ds>/<任务号小写>-<slug>，只在任务书「文件范围」内修改。
先完成「接单确认」；如任务书有问题请停止并说明，不要自行改范围。
完成后按 PR 模板提交 PR，如实填写命令、结果和 DoD 状态。不要合并。
```

**GPT 网页版**：把按[交接包模板](templates/HANDOFF_PACKET.md)填好的文件全文粘贴给它，并依文末“回传格式”要求回复；Human 把回复原文贴回对应 PR 或 Issue 评论。

**仓库操作员（GPT 网页版）的落盘请求**

```
请作为 LexAIDaily 仓库操作员，把下列文件原样提交到分支 claude/<任务号小写>-<slug>，并开 Draft PR（标题：<任务号> <标题>）。
不得增删改任何文字；发现问题请在回复中指出，不要自行修改。不要合并。
提交后回复：commit SHA、PR 链接、文件列表、CI 状态（或“未触发”）。
文件：<路径与内容>
```

## 5. 接单确认

执行者在 PR 草稿或评论中逐项确认：范围清晰、输入齐全、DoD 可验证、文件范围与其他在途任务无冲突、预计需要的授权已具备。任一项不成立即拒单，Claude 修订任务书后重新派发。

## 6. 结果复核

对每个 READY_FOR_REVIEW 的任务，按 [复核报告模板](templates/REVIEW_REPORT.md) 检查：

1. **范围**：diff 是否全部落在“可改文件”内；有无未授权依赖或配置。
2. **DoD**：逐项对照，每项必须有证据。
3. **证据真实性**：命令输出、CI 链接是否对应本次 commit；“未触发”“未执行”是否如实。
4. **红线**：密钥、冻结基线、编辑原则、许可证、AI 初稿标注。
5. **一致性**：文档、索引、STATUS 是否同步；链接是否可达。
6. **事实**：抽查来源链接，高风险条目全查。
7. **审计触发**：对照 AGENTS.md 6.1，需要则转 IN_AUDIT 并准备交接包。

结论三选一：`ACCEPT`（进入审计或 HUMAN_DECISION）、`CHANGES_REQUESTED`（列出 S1 阻断 / S2 重要 / S3 建议）、`ESCALATE`（交 Human）。复核意见发在 PR 评论，重要的另存 `docs/audits/<任务号>-claude-review.md`。

## 7. 升级给 Human 的情形

B 级任务；执行者与复核者争议；Claude 与 GPT 网页版审计分歧；已合并内容被发现有事实或合规问题；需要授权、付费或外部账号；DoD 无法达成而需改范围；优先级取舍；任何涉及法律专业判断或对外发布的事项。

决策包按 AGENTS.md 第 11 节写：

```
要你决定的事：<一句话>
我的建议：<选项 + 理由 + 代价>
其他选项：<…>
工作清单：
- [ ] 工作目标：…  工作链接：…  执行步骤：1. … 2. …
我不会代你做的事：<签署 / 批准 / 合并 / 发布>
```

## 8. 内容线日常（Gate 2 起）

编辑质检清单（对候选池逐条执行，只标注，不改写事实）：

1. 一手信源链接存在且可访问，不是二手转述。
2. “已证实事实 / 官方数据 / 市场观点”分层标注清楚。
3. 分类属于五类之一（模型与技术、实务与工具、监管与合规、判例与学术、行业与资本），无重复条目。
4. 摘要没有超出原文：数字、日期、机构名与原文一致，无新增事实。
5. 实务影响锚点已标注“AI 初稿”，没有下确定的法律结论。
6. 法律高风险条目已核对发布机构、发布日期、文件版本或效力状态；无法核实的标“未核实”，不写成确定事实。

命中高风险触发（立法、监管、司法文书、处罚、融资并购金额、涉及具体当事人的负面事实）的条目，生成交接包交 GPT 网页版二次核验，再交 Human。

## 9. 反模式

- 自己写、自己审、自己宣布通过。
- 没有证据就写“CI 通过”“测试通过”。
- 为赶进度悄悄降低 DoD，或不声明地扩大范围。
- 把 GPT 网页版或其他 Agent 的未核实结论当作事实转述。
- 发现问题后默默改掉而不记录；应写入复核意见，由原 Owner 修复。
- 把 B 级任务拆成多个 A 级任务来绕过授权，或不经 Human 确认就降级任务、豁免审计。
- 在对话里做决定却不落盘。
