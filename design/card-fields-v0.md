## 一、四要素与五类标签（原文转写）

`ROADMAP.md` Gate 1“核心任务 2”原文（逐字引用）：

> 设计标准资讯单元结构（“核心标题 + 精炼摘要 + 实务影响锚点 + 原始信源链接”）及五大分类标签体系（模型与技术、实务与工具、监管与合规、判例与学术、行业与资本）。

本 v0.2 只使用上述名称与顺序：

1. **四要素**：核心标题、精炼摘要、实务影响锚点、原始信源链接。
2. **五类标签**：模型与技术、实务与工具、监管与合规、判例与学术、行业与资本。

不新增、不改名、不合并、不拆分五类标签。`README.md` 第 3 节把标准单元简写为“核心标题 + 精炼摘要 + 实务影响 + 原始链接”；本表按 D01 以 ROADMAP 全称为准，简称不另立字段（差异处理见第十节第 3 条；README 为冻结基线，本任务不改）。

v0.2 新增的只是**展示层级**：四要素仍是标准单元的完整定义，列表卡片是它的摘录视图（见第二节）。

## 二、展示层级（Human 2026-11-11 指示，D-019）

同一份内容按展示位置分两层，各层展示字段是四要素的子集加状态位。

### 2.1 列表卡片（大盘、分类筛选、历史归档列表）

- 字段：核心标题、精炼摘要、原始信源链接、分类标签；加状态位（AI 初稿、未核实、事实层级）与“日期”“来源域名”；另加“重要度”（决定尺寸档位，见第四节）。
- **不展示实务影响锚点**（Human 指示，D-019）：列表卡片只承担扫读定位，实务影响属于需要阅读的内容，放详情页。
- 卡片尺寸随重要度与摘要长度变化（见第四、五节）；本表只定语义与长度档位，不写像素、字号与间距。

### 2.2 详情页

- 字段：列表卡片的全部字段，加**实务影响锚点**；详情页是四要素齐全的位置。
- 实务影响锚点的“AI 初稿”标识规则不变：Human 确认前必须标注（`AGENTS.md` 10.8），见第六节 6.1。
- 详情页的排版由 LD-G1-02B 设计系统定义；本表只约束字段与降级。

## 四、重要度（新增显示字段）

- 取值只有两个：**头条**、**常规**。缺省为“常规”。
- **由 Human 终审时勾选**；AI 不得自行标“头条”，也不得根据信源、阅读量或内容长度推断（D-019）。
- 作用：决定列表卡片的尺寸档位。v0.2 只定义语义与两值，具体档位（如 L/M/S 的尺寸、比例）由 LD-G1-02B 设计系统给出；本表不写视觉数值。
- 与“事实层级”无关：重要度是编辑排版权重，事实层级是内容性质；两者不得互相推导，也不构成信源可信度评价。

## 五、摘要长度档位

摘要仍为必填；档位只用于排版错落，不作数据校验。

| 档位 | 字数建议 | 排版含义 |
|---|---|---|
| 短摘要 | **少于 60 字** | 一句话事实型资讯；**不作缺陷处理**，仍必填，不因过短退回 |
| 常规摘要 | **60–120 字** | v0.1 原有的建议区间，默认档 |
| 长摘要 | **121–160 字** | 上限 160；超过 160 由排版截断（数据不截断），并在 PR/编辑环节提示压缩 |

- 卡片尺寸由重要度与摘要档位共同决定：同一重要度下，摘要越长卡片越高（Human 指示的“错落布局”，D-019）；具体比例由 LD-G1-02B 设计系统定义。
- 字数按中文字符计，含标点；这是排版预算，不是硬性校验。

## 六、三个状态显示位

### 6.1 “AI 初稿”

- 依据（`AGENTS.md` 10.8 原文）：
  > AI 生成的摘要、实务影响与点评，在 Human 确认前一律标注“AI 初稿”；不得把 AI 预审写成法律意见或人工批准。
- 显示对象：AI 生成且未经 Human 确认的**精炼摘要**（列表卡片与详情页均有）与**实务影响锚点**（仅详情页），逐字段标注。任务书 D03 的最低要求是实务影响锚点必须带；摘要由 AI 生成时同样带（AGENTS 10.8 覆盖“摘要”）。
- 位置与文案：紧贴对应字段，固定文案“AI 初稿”；Web 角标可 hover 说明，公众号行内文字不可省略。
- 移除：仅 Human 确认后移除；AI 不得自行去掉。
- 降级：字段来源未确认时默认显示（保守）。

### 6.2 “未核实”

- 依据（`AGENTS.md` 8.2 红线原文）：
  > 链接可访问不等于信息准确、现行有效，无法核实发布机构、日期、版本或效力状态的法律信息不得写成确定事实，须标“未核实”。
- 显示位置：卡片级状态位，紧邻分类标签；标识的是“发布机构、日期、版本、效力状态”的核验结果，不是资讯内容本身。
- 文案固定“未核实”；Web 可附 tooltip 说明核验对象，公众号用行内文字并在文末加一句说明（无 tooltip）。
- 移除：仅核验完成并经 Human 确认后移除；不得写成“已核实”推断。
- 降级：未提供核验结果时默认显示（保守）。

### 6.3 事实层级（Human 已采纳三档，D-016）

- 三档：**已证实事实 / 官方数据 / 市场观点**，与 `AGENTS.md` 8.2 红线及 `README.md` 第 4 节编辑原则 1（“已证实的客观事实”、“官方发布数据”、“市场观点评论”）对应。
- 展示：固定文案，置于分类标签同一行或卡片文末；缺失时不显示，不默认归入任何一档。
- **Human 已采纳三档（D-016）**：三档短称与展示位置（置于分类标签同一行或卡片文末）按本节保留；事实层级仍为条件显示，缺失时不显示，不默认归入任何一档。

## 七、占位标记

- **占位示例不再把“【示例占位】”写进标题**（Human 反馈标题重复标记太吵，D-019）。改为数据字段 `placeholder`：`true` 为虚构占位内容，`false` 为真实样本。
- UI 在卡片上显示小号“示例”标识（固定 2 字，不并入标题，不放大）；演示时一眼可辨，真实样本不显示。
- 示例文件 `card-fields-v0.example.json` 的 8 条全部 `placeholder: true`；真实样本为 `false`。
- 占位标记不替代“AI 初稿”“未核实”“事实层级”三个状态位：占位标记说明“内容是不是真的样本”，状态位说明“内容经没经过核实与确认”。

## 八、跨端显示规则

- **列表卡片**固定顺序：核心标题 → 分类标签与“未核实”/事实层级 → 精炼摘要（AI 生成时带“AI 初稿”）→ 原始信源链接 → 日期与来源域名；占位标记（`placeholder: true` 时）以角标显示。核心标题与原始信源链接不带“AI 初稿”标识（AGENTS 10.8 只覆盖 AI 生成的摘要、实务影响与点评）。
- **详情页**固定顺序：核心标题 → 分类标签与状态位 → 精炼摘要（同样带“AI 初稿”）→ 实务影响锚点（Human 确认前必须带“AI 初稿”）→ 原始信源链接。
- 列表卡片是摘录视图：**不**展示实务影响锚点（D-019），这是分层展示而非“把要素藏起来”；详情页四要素全展开，不再有二次点击才能看到的内容。
- 列表卡片须支持 3 分钟扫读（ROADMAP Gate 1 验收标准 3），因此不展示需要阅读的长文本；详情页承接实务影响。
- Web：桌面与移动断点、字号与间距由 LD-G1-02B 设计系统定义；本表只约束字段顺序、长度预算与降级。外链可直接点击，新标签打开。
- 公众号：样式全部内联；不依赖 hover；正文不依赖可点击外链，展示来源文本，跳转统一走“阅读原文”→ Web 详情页（ROADMAP Gate 1 核心任务 4），具体模板与真机预览由 LD-G1-03 验证。本表不对微信渲染兼容性下结论。

## 九、示例 JSON 说明

- 文件：`card-fields-v0.example.json`；共 8 条，五类标签齐全（各至少 1 条）。
- 全部为明显占位内容：每条 `placeholder: true`，标题不含“【示例占位】”字样，链接只用保留域名 `https://example.com/…`，正文为泛化表述，不含真实机构、事件与数字；不得作为事实引用。
- 覆盖情况：重要度“头条”3 条、其余“常规”；摘要短/常规/长三档各至少 2 条。
- JSON 键与显示名对应：

| JSON 键 | 显示名 | 说明 |
|---|---|---|
| `title` | 核心标题 | 字符串 |
| `summary` | 精炼摘要 | 字符串；档位按长度判断（第五节） |
| `impact_anchor` | 实务影响锚点 | 字符串；列表卡片不渲染，供详情页 |
| `source_url` | 原始信源链接 | 仅占位域名 |
| `category` | 分类标签 | 五类之一；单标签，五类取一（D-016） |
| `importance` | 重要度 | “头条”/“常规”；缺省“常规”，示例全部显式写出 |
| `placeholder` | 占位标记 | 布尔值；示例全部 `true` |
| `ai_draft_fields` | AI 初稿标识 | 字符串数组，列出需带“AI 初稿”的字段键 |
| `unverified` | 未核实标识 | 布尔值 |
| `fact_level` | 事实层级 | “已证实事实”/“官方数据”/“市场观点”或 `null` |

- 示例的“日期”与“来源域名”两个列表卡片字段：来源域名由 `source_url` 的域名部分取；日期由采集管线在 Gate 2 提供，**本示例文件不写日期**，以免编造具体时间（占位内容不含真实数字），草稿联调时按需在原型数据里补。
- `python3 -m json.tool design/card-fields-v0.example.json` 通过（结果见 PR）。
- 本示例文件不是 Gate 2 正式采集数据契约，不定义字段类型约束、唯一性、去重、抓取时间或信源评分。

## 十、Human 已决定的问题
