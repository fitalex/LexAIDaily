## 二、字段总表

下表每行即一个展示字段。长度参考是排版预算，不是数据校验规则（v0 不定义数据校验）。

| 字段（显示名） | 用途 | 必填/可选 | 排版用长度参考 | Web 与公众号两端的差异 | 缺失时的降级显示 |
|---|---|---|---|---|---|
| 核心标题 | 一眼判断这条资讯讲什么，是卡片主信息 | 必填 | 18–32 个汉字为宜，硬上限 40；桌面单行，移动/公众号最多 2 行 | Web 桌面单行大字号、移动 2 行；公众号最多 2 行、超长省略，完整标题在 Web 保留 | 不用摘要或链接代标题；该卡片不展示并标待补 |
| 精炼摘要 | 2–3 句说清事实，区分事实与观点 | 必填 | 60–120 个汉字为宜，上限 160；公众号控制在 4 行内 | Web 桌面 2–3 行、移动 3–4 行；公众号放宽行高、最多 4 行 | 不渲染摘要区，不用标题与锚点拼接代替；该卡片不展示并标待补 |
| 实务影响锚点 | 给法律从业者的实务影响提示；Human 确认前必须带“AI 初稿” | 必填 | 30–60 个汉字为宜，上限 80；2–3 行 | Web 用左侧色条或浅底色标记；公众号用行内底色并加“实务影响：”前缀，不用外部 CSS | 不渲染锚点区，不写“无影响”等推断；四要素不全，该卡片不展示并标待补 |
| 原始信源链接 | 读者回看一手来源，落实来源透明 | 必填 | 显示文本 12–40 个字符（域名 + 短标识）；完整 URL 不在卡片正文展示 | Web 可直接点击外链（新标签打开）；公众号正文不依赖可点击外链，展示来源文本，跳转经“阅读原文”→ Web 详情页（ROADMAP 核心任务 4） | 不渲染外链；该卡片不展示并标待补（AGENTS 8.2：无一手信源链接不入选） |

## 三、三个状态显示位

### 3.1 “AI 初稿”

- 依据（`AGENTS.md` 10.8 原文）：
  > AI 生成的摘要、实务影响与点评，在 Human 确认前一律标注“AI 初稿”；不得把 AI 预审写成法律意见或人工批准。
- 显示对象：AI 生成且未经 Human 确认的**精炼摘要**与**实务影响锚点**，逐字段标注。任务书 D03 的最低要求是实务影响锚点必须带；摘要由 AI 生成时同样带（AGENTS 10.8 覆盖“摘要”）。
- 位置与文案：紧贴对应字段，固定文案“AI 初稿”；Web 角标可 hover 说明，公众号行内文字不可省略。
- 移除：仅 Human 确认后移除；AI 不得自行去掉。
- 降级：字段来源未确认时默认显示（保守）。

### 3.2 “未核实”

- 依据（`AGENTS.md` 8.2 红线原文）：
  > 链接可访问不等于信息准确、现行有效，无法核实发布机构、日期、版本或效力状态的法律信息不得写成确定事实，须标“未核实”。
- 显示位置：卡片级状态位，紧邻分类标签；标识的是“发布机构、日期、版本、效力状态”的核验结果，不是资讯内容本身。
- 文案固定“未核实”；Web 可附 tooltip 说明核验对象，公众号用行内文字并在文末加一句说明（无 tooltip）。
- 移除：仅核验完成并经 Human 确认后移除；不得写成“已核实”推断。
- 降级：未提供核验结果时默认显示（保守）。

### 3.3 事实层级（提议，待 Human 确认）

- 三档：**已证实事实 / 官方数据 / 市场观点**，与 `AGENTS.md` 8.2 红线及 `README.md` 第 4 节编辑原则 1（“已证实的客观事实”、“官方发布数据”、“市场观点评论”）对应。
- 展示：固定文案，置于分类标签同一行或卡片文末；缺失时不显示，不默认归入任何一档。
- **本项为提议**：是否启用三档、是否采用该短称、是否与分类标签同排，均待 Human 确认（D03 要求标注）；Human 确认前只作原型示意，不构成已定规则。

## 四、跨端显示规则

- 卡片内固定顺序：核心标题 → 分类标签与“未核实”/事实层级 → 精炼摘要（AI 生成时带“AI 初稿”）→ 实务影响锚点（Human 确认前必须带“AI 初稿”）→ 原始信源链接。核心标题与原始信源链接不带“AI 初稿”标识（AGENTS 10.8 只覆盖 AI 生成的摘要、实务影响与点评）。
- 四要素默认全展开，不把任一要素藏在点击或展开之后；单期内容要支持 3 分钟扫读（ROADMAP Gate 1 验收标准 3）。
- Web：桌面与移动断点、字号与间距由 LD-G1-02 设计系统定义；本表只约束字段顺序、长度预算与降级。外链可直接点击，新标签打开。
- 公众号：样式全部内联；不依赖 hover；正文不依赖可点击外链，展示来源文本，跳转统一走“阅读原文”→ Web 详情页（ROADMAP Gate 1 核心任务 4），具体模板与真机预览由 LD-G1-03 验证。本表不对微信渲染兼容性下结论。

## 五、示例 JSON 说明

- 文件：`card-fields-v0.example.json`；共 5 条，五类标签各 1 条。
- 全部为明显占位内容：每条标题含“【示例占位，非真实资讯】”，链接只用保留域名 `https://example.com/…`，不含任何真实新闻事实；不得作为事实引用。
- JSON 键与显示名对应：

| JSON 键 | 显示名 | 说明 |
|---|---|---|
| `title` | 核心标题 | 字符串 |
| `summary` | 精炼摘要 | 字符串 |
| `impact_anchor` | 实务影响锚点 | 字符串 |
| `source_url` | 原始信源链接 | 仅占位域名 |
| `category` | 分类标签 | 五类之一；用字符串仅为原型展示，不预设多标签结论（第六节第 1 条） |
| `ai_draft_fields` | AI 初稿标识 | 字符串数组，列出需带“AI 初稿”的字段键 |
| `unverified` | 未核实标识 | 布尔值 |
| `fact_level` | 事实层级 | “已证实事实”/“官方数据”/“市场观点”或 `null`；提议项 |

- `python3 -m json.tool design/card-fields-v0.example.json` 通过（结果见 PR）。
- 本示例文件不是 Gate 2 正式采集数据契约，不定义字段类型约束、唯一性、去重、抓取时间或信源评分。

## 六、待 Human 决定的问题

1. **一条资讯能否带多个分类标签？** 本 v0 不自行决定：字段表与示例按“每条只带一个标签”展示，示例的 `category` 用字符串仅为原型展示，不预设“单标签”结论；若允许多标签，字段是否改为数组、标签如何排序，请 Human 决定。
2. **事实层级是否采纳？** 三档短称与展示位置为提议（第三节 3.3），请 Human 确认是否启用。
3. **README 简称与 ROADMAP 全称的差异如何处理？** README 第 3 节用“实务影响”“原始链接”，ROADMAP 用“实务影响锚点”“原始信源链接”；本表以 ROADMAP 为准（D01），未改 README（冻结基线）。是否需要另行对齐，请 Human 决定。
