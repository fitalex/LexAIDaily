# 「阅读原文」联动动线设计（LD-G1-03 / D-030）

> 状态：动线设计稿。本文只描述公众号栏目与 Web 详情页的衔接方式，**不实现跳转**；外链限制由 Gate 3 解决。占位域名 `lexaidaily.example` 为保留示例，不对应任何真实站点。

## 一、要解决的问题

微信公众号正文只允许极少数外链形态（公众号文章、已授权白名单、小程序等），**不能给每条资讯放一个直达原始信源的 `<a href>`**。而 D-030 要求：公众号单条资讯保留 1 句极简「实务影响」，完整实务锚点与一手信源放到 Web 详情页。

因此采用**单入口跳板**：公众号文章全文只有一个「阅读原文」，指向 Web 端的**当日详情页**；读者在 Web 页内查看每条资讯的完整实务锚点并点开一手信源。

## 二、动线

```text
[微信公众号 · 每日固定栏目]
   │  每条资讯：编号 · 五类标签 · 标题 · 摘要 · 1 句实务影响（AI 初稿）· 信源名称与日期
   │  每条资讯末尾：文字引导「第 NN 条 · 完整实务锚点与一手信源 → 阅读原文」
   │  文末：阅读原文引导区（1px 黑框，写明当日 Web 详情页 URL 与说明）
   ▼  文章底部唯一入口「阅读原文」（后台设置，不在正文 HTML 中）
[Web 当日详情页]  https://lexaidaily.example/d/2026-11-24
   │  · 当日 14 条完整列表，每条对应锚点 #item-01 … #item-14
   │  · 完整摘要 + 完整实务影响锚点（AI 初稿）+ 事实层级 + 来源域名
   │  · 「直达一手信源 ↗」按钮（新标签打开）
   ▼
[原始信源]  ICO / 欧盟委员会 / arXiv / 法院官网 / 厂商新闻稿 …
```

## 三、URL 约定（占位，待 Gate 3 定稿）

| 项 | 约定 | 说明 |
|---|---|---|
| 当日详情页 | `https://lexaidaily.example/d/{YYYY-MM-DD}` | 例：`/d/2026-11-24`；`lexaidaily.example` 为保留域名占位 |
| 单条锚点 | `{当日详情页}#item-{NN}` | 例：`#item-01`；供 Web 内跳转与站内分享，**公众号正文不直接使用** |
| 公众号「阅读原文」 | 当日详情页根地址 | 微信每篇文章只允许一个「阅读原文」链接，无法按条区分 |
| 一手信源 | 由 Web 详情页的「直达一手信源」按钮承载 | 公众号正文只显示信源名称与日期，不出现 URL |

## 四、公众号侧如何呈现

- **正文内不放置任何 `<a href>`、二维码或外部 URL 文本**；只有文字引导「→ 阅读原文」。
- 每条的「第 NN 条 · 完整实务锚点与一手信源 → 阅读原文」是**视觉引导**，点击行为统一由文章底部的「阅读原文」承担；读者需按编号在 Web 页找到同一条。
- 文末「阅读原文」引导区展示当日 Web 页地址（纯文本，不可点），并注明“微信正文不支持直接外链；请在公众号后台将「阅读原文」指向上述 Web 详情页”。
- 「阅读原文」入口本身**必须在公众号后台手动设置**（文章编辑页 → 阅读原文 → 填写链接）；HTML 无法代替该设置，本任务也不接触后台与凭据。

## 五、为什么用 Web 详情页做跳板

1. **合规**：公众号正文只给摘要，不整篇转载；一手信源在 Web 页统一展示，来源可追溯。
2. **信息完整**：公众号单元只保留 1 句实务影响（D-030）；完整锚点、事实层级、来源域名与直达按钮都在 Web 页。
3. **可替换**：公众号「阅读原文」只有一个链接，Web 页可以按日聚合、按条锚点定位，不必为每条资讯各开一个入口。
4. **可演进**：Gate 3 接入正式域名、外链策略与（如需要）跳转统计时，只需替换「阅读原文」目标，不必改公众号模板。

## 六、微信限制与 Gate 3 边界

- **本任务不实现**：正式域名、Web 详情页、短链、跳转统计、白名单申请、小程序跳转、二维码。
- **Gate 3 解决**：正式域名与部署、公众号外链可行路径（白名单 / 小程序 / H5）、失效链接处理、访问统计与隐私合规。
- **待 Human 决定**：正式域名；「阅读原文」是固定指向当日页还是栏目首页；是否需要在 Web 页提供“复制引用格式”；正文是否展示来源域名（当前只展示机构名与日期）。
